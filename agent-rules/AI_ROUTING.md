# AI・モデル選定と実績管理

- Version: 0.1.0
- Status: Pilot
- Last verified: 2026-08-16
- Applies to: Codex / Claude Code

この文書は、作業ごとにAI基盤とモデルを選び、結果を記録して次回の選定を改善するための正本です。モデルの一般的な性能順位ではなく、作業の曖昧さ、影響範囲、検証可能性、実行環境、利用可能量で決めます。

## 1. 作業開始時の決定記録

Issueまたは作業開始報告へ、次を記録します。

```yaml
assignment:
  platform: Codex | Claude Code | Dual review
  model: Sol | Terra | Luna | Opus | Sonnet | opusplan
  effort: low | medium | high | xhigh | max | default
  risk: low | medium | high | critical
  reason: 選定理由
  fallback: 失敗・上限・利用不可時の切替先
```

ユーザーが指定したAI・モデルは優先します。自動選定は指定がない場合だけ行い、切替時は理由を残します。

## 2. AI基盤の選択

| 状況 | 第一候補 | 理由・運用 |
|---|---|---|
| PC・クラウド・GitHubをまたいで調査からPR・Issue・公開確認まで行う | Codex | この運用の既定。GitHub作業とクラウド継続を一つの流れで管理しやすい |
| 既存のClaude Codeセッション、作業ブランチ、CLAUDE.mdの文脈を引き継ぐ | Claude Code | 文脈の再読込と作業重複を避ける |
| ローカルPCで対話しながら計画と実装を切り替える | Claude Code `opusplan` またはCodex Sol/Terra | `opusplan`は計画をOpus、実装をSonnetへ分けられる。Codexでは作業難度に応じSol/Terraを選ぶ |
| 重要変更を独立レビューする | 実装担当と別のAI基盤 | 同じ見落としや思い込みを引き継ぐ相関エラーを減らす |
| 片方が利用上限・接続・権限で止まる | もう一方 | 状態、未完了事項、検証結果をIssueへ残してから交代する |

AI基盤の選択だけで品質を保証しません。リポジトリへのアクセス、実行可能な検証、未コミット状態、公開権限を先に確認します。

## 3. 現行モデルの役割

### Codex

| モデル | 任せる作業 | 任せない／上位へ切り替える条件 |
|---|---|---|
| Sol | 曖昧な要件、設計、根本原因不明の不具合、広範な変更、高リスク実装、最終レビュー、監査 | 完了条件が単純で大量反復ならTerra/Lunaを検討 |
| Terra | 通常実装の既定。明確な機能追加、複数ファイル修正、テスト追加、一般的な不具合修正 | 要件自体の判断、高リスク、大規模横断、2回失敗でSolへ |
| Luna | 文言、文書、限定CSS、定型変換、明確なテスト追加、schemaで検証できる反復作業 | 設計、保存移行、依存関係、公開、認証・課金・セキュリティ、正確性判断、原因不明では使わない |

OpenAI公式の役割は、Solが複雑で自由度の高い作業、Terraが日常作業、Lunaが明確で反復可能な作業です。推論強度は必要な結果を満たす最小値から始め、複数段階の判断やトレードオフが増えるほど上げます。

### Claude Code

| モデル／モード | 任せる作業 | 切替条件 |
|---|---|---|
| Opus | 複雑なagentic coding、長い推論、設計、根本原因調査、高リスク変更、最終レビュー | 明確な通常実装はSonnetへ |
| Sonnet | 通常実装の既定。速度と品質のバランスが必要な明確な作業 | 曖昧、高リスク、長期化、2回失敗でOpusへ |
| `opusplan` | 設計判断は難しいが実装手順が固まれば通常難度になる作業 | 実装中も判断が連続する場合はOpusを維持 |

Claude Codeの`opus`・`sonnet` aliasはproviderとバージョンで解決先が変わるため、作業記録には可能なら実際のモデル名も残します。

## 4. リスクとモデルの最低基準

| リスク | 例 | 最低基準 |
|---|---|---|
| Low | 文言、文書、限定的な見た目、定型データ | Luna / Terra / Sonnet |
| Medium | 通常の機能追加、複数ファイル修正、一般的な不具合 | Terra / Sonnet |
| High | 永続データ、依存関係、音声、PWA、CI、公開、教材判定、大規模生成 | Sol / Opus。別AIレビューを原則実施 |
| Critical | データ損失、認証、課金、セキュリティ、本番破壊、不可逆移行 | Sol / Opus。実装と独立レビューを分離し、人の承認点を置く |

軽量モデルで開始後にHigh以上と判明した場合、その時点で停止して引き継ぎ記録を作り、上位モデルへ切り替えます。

## 5. 作業種別の既定ルーティング

| 作業 | 既定 | 代替・レビュー |
|---|---|---|
| 新規アプリの構想・アーキテクチャ | Codex Sol またはClaude Opus | 重要判断は別AIでレビュー |
| 明確な機能追加・通常の不具合修正 | Codex Terra | Claude Sonnet |
| 原因不明、再現困難、複数回失敗した不具合 | Codex Sol | Claude Opus |
| 1画面の文言・軽微CSS | Codex Luna | 崩れや判断が出たらTerra |
| 大量の定型データ整形 | Codex Luna | schema・件数・重複を自動検証。意味判断はSol/Opus |
| 教材・金融・医療など正確性が重要な内容 | Codex Sol またはClaude Opus | 出典・計算・正答を独立検証 |
| 保存形式・migration | Codex Sol またはClaude Opus | 別AIレビュー＋旧データfixture |
| CI・公開設定・依存関係 | Codex SolまたはTerra high | 影響が大きければOpusレビュー |
| 既存PRの最終コードレビュー | 実装担当と別AIのSol／Opus | 指摘後は対象テストを再実行 |

## 6. 強制エスカレーション条件

次のいずれかで上位モデルまたは別AIへ切り替えます。

1. 同じ仮説・方針で2回失敗した。
2. 根本原因を説明できないまま差分だけが増えている。
3. 予定外の高リスク領域、依存関係、migration、公開設定へ変更が広がった。
4. テスト結果、実装説明、実際の差分が矛盾する。
5. コンテキスト圧縮や利用上限後に、決定事項または未完了状態を復元できない。
6. 軽量モデルが要件解釈や仕様判断を始めた。

交代時は、目的、判明した事実、試したこと、失敗結果、現在差分、未実行テスト、次の完了条件をIssueへ残します。

## 7. 完了時の実績記録

PRまたはIssueへ次を追記します。

- 実際に使ったAI基盤・モデル・推論強度
- 途中切替と理由
- 初回で完了条件を満たしたか
- 再試行回数
- 独立レビューのAI・モデルと重要指摘数
- 未実行検証と残存リスク

月次または10件ごとに、作業種別別の初回成功率、手戻り、重大見落とし、利用上限による中断を比較します。体感だけで恒久ルールを変えず、Issueに残った実績で更新します。

## 8. 更新ルール

- モデルの新設、廃止、alias変更時は公式資料を確認し、モデル表だけを更新する。
- 作業の安全基準とエスカレーション条件は、モデル名から独立させる。
- 特定repoではAGENTS.mdの固有ルールがこの文書より厳しい場合、固有ルールを優先する。
- モデルが利用できない場合は、同じリスク水準を満たす代替を選び、下位モデルへ無言で落とさない。
